# 영상 수집 및 검토 운영
- 자동 수집은 6시간 간격의 GitHub Actions 예약 작업입니다. 실제 수집은 YouTube Data API v3를 활성화하고 저장소 Actions secret YOUTUBE_API_KEY를 설정한 이후에만 동작합니다. 키가 없으면 안전하게 건너뜁니다.
- sources.json에 검색어, 원 제작자 채널 ID, 재생목록 ID를 관리합니다. 공식 API에서 공개, 한국 지역 재생 가능, 임베드 허용, 연령 제한 없는 후보를 수집합니다. 실제 재생 가능 여부, AI 생성 여부, 한국어 음성 및 제작자 권리는 사람이 확인해야 합니다.
- Actions의 flix-review artifact에서 candidates.json 및 health.json을 내려받습니다. 데이터는 7일 후 만료됩니다. 이미 등록한 영상은 후보에서 제외하고 상태만 점검합니다. 자동 삭제/공개는 하지 않습니다.
- approvals.example.json을 복사하여 실제 후보 ID, 작품·회차·장르·언어·검토자 등을 입력하고 승인할 항목만 approved:true로 바꿉니다. node scripts/flix-catalog-review.mjs approvals.json 실행 시 flix-review/approved-catalog.json 생성. 원본 catalog는 수정하지 않습니다. 검토 후 기존 public/flix/catalog.json과 diff를 확인하고 PR로 등록합니다.
- 기존 사이트는 archive/pre-flix-2026-11-26에 보존. Firestore 데이터와 규칙은 변경하지 않습니다. 관리자 웹 화면 및 대규모 자동 분류는 아직 별도 단계입니다.

## 로컬 관리자 화면
저장소를 내려받고 루트에서 `node scripts/flix-admin.mjs` 실행 후 http://127.0.0.1:8765 접속. 카탈로그와 수집 결과 JSON을 불러와 작품·회차 편집, 삭제, 후보 승인 및 검증된 JSON 내보내기를 수행합니다. 저장소 권한이 있는 운영자가 PR로 공개합니다. 로컬 전용이며 공개 호스팅이나 Firebase 인증/규칙을 변경하지 않습니다.

## 직접 링크 등록
로컬 관리자 실행 시 현재 카탈로그 자동 불러오기. 유튜브 URL 또는 여러 URL 붙여넣기, 재생목록 및 채널 조회, 중복 표시, API 확인 결과, 새 작품/기존 작품 회차 추가, 검토 확인, 편집 및 검증 후 JSON 내보내기. 로컬 서버의 환경변수 YOUTUBE_API_KEY를 설정하면 공식 API 정보를 채웁니다. 키 미설정 시 개별 링크에서 영상 ID만 추출하며 메타데이터 및 재생 여부 수동 검토가 필요합니다. 재생목록/채널은 키 필요. 채널·재생목록 수집 설정 초안도 내보낼 수 있습니다. 공개 사이트에는 관리 기능을 배치하지 않습니다.
GitHub 로그인 후 Actions > AI영상 링크 등록 및 검토 > Run workflow에서 서버 측 secret으로 조회 가능. approved는 검토 후 공개용 카탈로그 초안을 생성하는 옵션이며 자동 공개는 하지 않습니다. 결과 artifact의 approved-catalog.json을 검토하여 PR로 등록합니다. 공개 사이트 관리자 로그인/직접 저장은 별도 인증·권한 설정 필요.

## 온라인 관리자 (/admin/)
Firebase Hosting의 https://sosoking-481e6.web.app/admin/ 에서 이메일/비밀번호 또는 Google 인증 후 로그인합니다. Firebase Authentication에서 로그인 공급자를 활성화하고 운영자 계정을 생성/로그인한 후, Firebase 콘솔 Firestore의 flixAdmins 컬렉션에 운영자의 실제 UID를 문서 ID로 등록해야 합니다 (enabled:true 필드 예시). 브라우저는 관리자 권한을 생성할 수 없습니다. 로그인만 한 일반 계정은 편집 또는 공개 저장 권한이 없습니다.
관리자는 작품/회차 편집, 링크 ID 가져오기(제목/제작자 등 수동 확인), 후보 JSON 검토, 백업, 공개 반영을 수행합니다. 공개 반영은 flixPublic/catalog 문서에 JSON 및 revision을 저장하는 트랜잭션입니다. 기존 static catalog는 최초 목록 및 오류시 폴백으로 사용합니다. 이후 GitHub 카탈로그 변경은 온라인 공개본을 자동으로 덮어쓰지 않습니다. 동시 편집 충돌은 버전 검사로 방지합니다. 공개본 크기 700KB 제한. 웹 관리자에 API 키가 노출되지 않도록 YouTube API 조회는 GitHub 검토 또는 로컬 도구에서 합니다. 온라인 공개본과 정기 수집 후보의 자동 승인/연동은 아직 별도 개발입니다.
기존 Firestore 규칙의 원문과 배포된 활성 규칙이 일치할 때만 영상 관리자 전용 경로를 추가합니다. 원문 불일치·권한 부족 시 규칙 배포를 중지하고 Firebase 콘솔에서 기존 규칙을 보존한 채 검토해야 합니다. CI에서 Firestore emulator로 비인가 저장, 권한 자체 생성, 정상 관리자 저장 및 공개 읽기 등을 검사합니다.

## 운영 자동화
온라인 관리자에서 링크 서버 조회를 요청하면 flixAutomation/lookup에 관리자 전용 요청이 생성되고, 10분 주기 GitHub Actions가 서버 secret으로 조회합니다(예약 지연 가능). 조회가 지연되거나 키가 없으면 개별 링크 수동 등록을 사용하세요. 동일 요청 진행 중 중복 제출 방지, 결과는 관리자만 읽기 가능. 정기 회차 추적은 6시간마다, 신규 추적 설정은 다음 예약 작업에서 우선 검사합니다. 최초 영상 제목이 정확히 작품명+1화 형태이고 동일 채널/공통 제목/회차가 연속하며 외부 재생 가능 확인 시에만 자동 공개합니다. 명시적 자동 공개 체크가 없는 경우 후보 검토만 합니다. 중복·예고편·몰아보기·누락 또는 복수 후보는 자동 공개 제외. 검색 결과는 작품당 최대 100개, 한 번에 8작품씩 순환 처리. 자동 등록은 공개 Firestore 카탈로그 버전 확인 후 적용됩니다. 관리자 화면에서 숨긴 작품은 시청 목록에서 제외하고 추적을 멈춥니다. Firebase 통계는 실제 활성화 및 데이터 수집 여부 확인 필요, 허위 통계 표시 없음.

운영 보고서에는 신규 AI 작품 검색 후보 및 재생 제한 검사 결과도 표시합니다. 일반 작품은 관리자 검토 후 등록하며, 이용 통계는 Firebase Analytics가 연결되어 있고 시청자가 선택적으로 통계를 허용한 경우에만 이벤트를 기록합니다. 별도 이용자 ID나 시청 이력을 통계 이벤트에 넣지 않으며 실제 통계는 Firebase 콘솔에서 확인합니다. Analytics 미설정 시 통계 수집 없이 시청 가능합니다.

기존 후보 수집 workflow는 중복 API 사용 방지를 위해 수동 실행 전용으로 전환합니다. 온라인 운영 worker가 정기 검색과 재생 검사, 추적을 담당합니다. YouTube API 쿼터 및 GitHub 예약 실행 지연에 따라 실제 처리 시간이 달라지며, 검색 범위를 넘는 작품은 수동 검토가 필요합니다.

## 검색 최적화
메인 페이지의 실제 HTML에 공개 작품 목록 및 WebSite 구조화 데이터를 넣고 /works/, /category/drama/, /category/film/, /category/animation/ 및 작품별 /works/{id}/ 페이지를 생성합니다. sitemap.xml에는 공개 작품 및 실제로 생성된 분류 주소만 포함합니다. 작품 페이지는 소개 및 회차 탐색 페이지이며 재생은 기존 플레이어 링크로 이동합니다. 실제 영상 업로드일 등이 불확실한 영상에 VideoObject를 생성하지 않습니다. main Hosting 배포 시 Firestore의 현재 공개 카탈로그를 읽어서 검색용 HTML과 사이트맵을 생성하며 매일 예약 배포로 갱신합니다. 공개/숨김 변경은 다음 갱신 전까지 검색용 페이지에 남을 수 있습니다. 검색 노출과 순위는 보장하지 않습니다. 네이버/구글에 제출: https://sosoking-481e6.web.app/sitemap.xml. 기존 소유 확인 방식은 유지하고 인증 토큰을 임의 생성하지 않습니다.

## 기존 관리자 계정 호환
기존 Firebase admins 컬렉션의 UID 문서 또는 인증된 이메일과 정확히 동일한 문서 ID를 사용합니다. flixAdmins의 UID 문서도 호환 유지됩니다. enabled:false인 문서는 권한으로 인정하지 않습니다. 관리자 문서는 콘솔/신뢰된 서버에서만 관리하며 클라이언트는 자신의 문서만 조회하고 관리자 문서를 생성·수정할 수 없습니다. 기존 컬렉션 및 문서는 삭제, 복사 또는 이름 변경하지 않습니다. 이메일 등록 방식의 링크 조회 워커는 서비스 계정의 Firebase Authentication 사용자 조회 권한도 필요합니다.

## 방문 및 시청 통계
관리자 대시보드에서 이용 통계를 확인합니다. Firebase Authentication의 익명 로그인 공급자 활성화가 필요합니다. 방문자는 회원가입이나 이메일 입력 없이 시청하며 통계를 허용한 경우에만 별도 익명 Firebase 인증 식별자로 기록합니다. 60초 간격의 제한된 heartbeat, 최근 120초 신호를 기준으로 동시 접속과 재생 중 브라우저를 근사합니다. 전경 페이지에서 재생 상태일 때만 시간을 누적하며 종료 직전 일부 구간, 백그라운드 재생, 네트워크 장애는 누락될 수 있습니다. 한국시간 날짜 기준으로 오늘, 최근 7일 및 30일 지표와 작품별 재생시간 순위를 집계합니다. 동의 취소 시 수집 중지, 기존 익명 지표는 35일 기준 예약 삭제. 관리자만 타 브라우저 통계 읽기 가능. Firestore 비용 보호를 위한 속도 제한 및 관리자 조회 상한이 적용되며, 여러 브라우저/기기·쿠키 삭제와 미동의 사용자는 정확한 실제 사람 수와 차이가 있습니다. Analytics가 설정되면 유입 경로와 기기 통계는 Firebase 콘솔에서 확인 가능합니다.

## YouTube 소통 및 스튜디오 UI
Google Cloud OAuth 동의 화면과 웹 애플리케이션 OAuth 클라이언트를 생성합니다. 승인된 JavaScript 원본은 https://sosoking-481e6.web.app 입니다. GitHub repository Variables에 YOUTUBE_OAUTH_CLIENT_ID를 넣습니다. 공개 댓글 및 통계 조회용으로 별도의 YouTube Data API v3 전용 HTTP referrer 제한 키를 발급하고 https://sosoking-481e6.web.app/*만 허용한 후 YOUTUBE_PUBLIC_API_KEY 변수에 넣습니다. 기존 서버 YOUTUBE_API_KEY secret을 절대로 공개 브라우저 키로 재사용하지 않습니다. 다음 Hosting 배포에서 공개 클라이언트 ID와 제한 키가 youtube-config.json에 반영됩니다. OAuth 클라이언트 secret은 필요 없으며 소스 또는 변수에 넣지 않습니다. Google 테스트 사용자 및 외부 공개 앱 검증, 도메인 소유 확인, 실제 운영자 연락처와 개인정보 안내 검토가 완료되어야 일반 사용자 공개를 시작할 수 있습니다. 설정이 없으면 연결/공개 조회가 제한되며 원본 유튜브 링크와 시청은 계속 가능합니다. 토큰은 메모리 전용, 댓글/답글/좋아요는 사용자 명시 행동만 전송, 원본 API 결과는 DB 미저장. 통합본은 동일 영상 댓글/좋아요 공유. 공개 API 한도 관리 및 실제 계정 테스트 필요.

## 자동 수집 품질 기준
연재형 본편은 회차 표시 및 5분 이상, 회차 통합본은 10분 이상, 회차 없는 인기 본편은 10분 이상 및 조회수 3,000회 이상으로 제한. 쇼츠·숏폼·단편 표기·예고편·하이라이트·제작 강의 등 제외. 회차 추적에는 조회수 하한을 적용하지 않아 공개 직후 신규 본편을 놓치지 않도록 합니다. 자동 후보는 연재형 우선, 조회수 순으로 정렬. YouTube Data API는 쇼츠를 별도 확정 분류하는 필드를 제공하지 않으므로 재생시간 및 제목/태그를 이용합니다. 수동 링크 등록과 이미 공개된 목록 및 재생 상태 검사는 그대로 유지합니다. 정책 버전 변경 시 기존 후보 재검사 및 신규 검색을 실시합니다.
