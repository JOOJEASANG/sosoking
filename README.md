# SOSOKING — 나의 하루체크

https://sosoking-481e6.web.app/

2026-11-19 기준 소소킹의 기존 프로그램 모음을 하루체크형 일기 서비스로 완전히 재설계했습니다. 이전 코드 버전은 GitHub의 archive/pre-daily-check-2026-11-19 브랜치로 백업했습니다.

## 주요 기능

- 오늘 체크: 생활·먹거리·사람·재미 카테고리의 기본 항목을 탭 한 번으로 기록. 체크박스형, 횟수형(0~999), 선택지형(2~5개).
- 나만의 항목: 2~60자 제목, 종류, 카테고리 지정.
- 모두의 항목: 사용자가 체크 항목의 정의만 Firestore에 저장. 다른 이용자가 선택해 자기 기록에 추가.
- 내 기록: 이전 날짜, 월별 달력, 이번 달 기록일·체크 수, 연속 기록일.
- 보관/복원: 개인 일기와 개인 항목은 기기 브라우저 localStorage에만 저장. JSON 내보내기·가져오기와 초기화.
- 항목 관리: 기본 항목 및 자신이 추가한 항목을 체크 목록에서 숨기거나 다시 표시.
- PWA: 단일 공개 앱 셸은 오프라인 캐시, Firebase API/개인 기록은 캐시하지 않음.

## 프라이버시 및 운영 경계

- 개인 하루 일기는 기본 비공개이며 서버에 저장하지 않음. 다른 사람과 기록을 공유하거나 서버 동기화하는 기능은 없음. 기기 변경 시 JSON 백업이 없으면 복원이 어려움.
- 공유 항목에는 제목, 유형, 분류, 선택지만 저장. 이름·전화번호·민감한 개인정보는 공유 항목 제목에 기재하지 않도록 안내.
- 공용 항목 추가는 Firebase 익명 인증으로만 가능하며 하나의 익명 UID당 24시간에 1건으로 서버 규칙 제한. 익명 사용자 ID 재생성까지 완전히 방지하지는 못함.
- 신고는 항목별 UID당 1건. 운영자는 신뢰할 수 있는 Admin 권한으로 moderators/{uid} 문서를 만들고 신고를 검토한 뒤 항목 삭제 가능. 별도 운영자 검수 UI나 사전 자동 검수는 아직 없음.
- 기존 events 등 Firestore 문서는 삭제하지 않았으며, 새 보안 규칙에서 일반 접근을 차단. 복원에는 옛 브랜치와 권한 규칙의 신중한 재배포가 필요. 이전 고객 데이터에 대한 삭제 정책은 별도 결정.
- 옛 프로그램 HTML·JS·테스트는 새 main 브랜치와 Hosting 배포에서 제거. 옛 프로그램 URL은 404.
- 광고·제3자 추적 도구는 설치하지 않음.

## 개발 및 배포

npm install, npm run check, npm run build, npm run dev.

Firebase 설정은 Hosting /__/firebase/init.json에서 읽음. 클라이언트 공유 항목은 publicItems, 공유 빈도 제한은 contributorLimits, 신고는 itemReports 컬렉션 사용.

GitHub Actions main 브랜치 자동 배포: 유닛 테스트, PWA 및 SEO 확인, Firebase Rules/Hosting 배포, 임시 테스트 항목 생성·권한 검사·삭제.

검색 사이트맵에는 공개 홈페이지 URL만 포함. Search Console과 Naver Search Advisor의 사이트 등록 및 소유권 확인은 별도.
