# SOSOKING — 작지만 쓸모 있는 프로그램

https://sosoking-481e6.web.app/

여러 소형 웹 프로그램을 추가할 수 있도록 설계된 웹 도구 모음입니다. AI를 사용하지 않습니다.

## 검색엔진 노출(SEO) 및 공개 서비스 안내

- `robots.txt`에 Google·Naver 등 검색로봇의 공개 사이트 수집 허용과 `sitemap.xml` 경로를 안내.
- `sitemap.xml`은 홈페이지, 모임집계, 옛 번호 변환기, 이용안내, 명단정리, 주문모아, 카톡정리 등 7개 **공개 페이지**만 포함. 행사별 실제 초대 링크(`event.html?id=...`)와 개인정보를 검색엔진에 제공하지 않음.
- 각 페이지마다 개별 제목, 메타 설명, canonical, Open Graph, 소소킹 공유 이미지, Schema.org JSON-LD 마크업 적용.
- 행사·번호 변환 페이지 하단에 검색로봇이 JavaScript 실행 없이 볼 수 있는 공개 기능 설명 추가.
- `/guide.html`에 총괄자·담당자별 이용 방법, 비밀번호 승인 흐름, 실제 개인정보 수집 방식과 삭제 방식, 광고 미사용 현황을 공개. 현재 안내는 법률상 필요한 운영자 정보가 포함된 공식 개인정보처리방침을 대체하지 않으므로, 광고 신청·상용 서비스 운영 전 해당 방침을 완비해야 함.
- 현재 방문자에게 광고 코드를 삽입하지 않았으며, `ads.txt`는 광고 게시자 계정 발급 전까지 생성하지 않음.
- Google Search Console: https://search.google.com/search-console
- NAVER Search Advisor: https://searchadvisor.naver.com/
- **사이트 소유권 인증과 사이트맵 제출은 사이트 소유자가 계정에 로그인하여 별도로 진행해야 함.** XML sitemap과 robots.txt 게시만으로 검색 결과 등록이나 검색 순위를 보장하지 않음.
- 배포 전 `node scripts/verify-seo.mjs --built`와 배포 후 공개 사이트 `robots.txt`, `sitemap.xml` HTTP 응답 검사.

## 통합 앱 로고 및 설치(PWA)

- 메인, 모임집계, 옛 번호 변환 모두 동일한 `public/icons/sosoking.svg` 소소킹 로고 사용.
- 빌드 시 `@resvg/resvg-js`로 파비콘 32px, iOS 홈 화면 아이콘 180px, Android 192/512px 및 마스커블 512px 생성.
- 모든 페이지에 설치 버튼이 있으며 Android Chrome의 설치 이벤트 지원 시 기본 설치 안내를, iPhone/미지원 브라우저에서는 홈 화면 추가 방법을 안내.
- `manifest.webmanifest`의 앱 시작 URL은 홈페이지 `/`. 설치한 앱 안에서 각 프로그램으로 이동할 수 있음.
- `sw.js`는 공개 정적 파일만 네트워크 우선으로 캐시함. 행사 참가자 정보, 인증 정보, Firebase API 응답은 절대로 캐시하지 않음.
- 행사 생성/승인/수정은 인터넷이 연결되어야 동작함.
- `npm run build && node scripts/verify-pwa.mjs`로 생성된 PNG 및 설정 검증.

## 확장 프로그램(2026-11-19)

- **명단정리** (`/roster.html`): 붙여넣기/CSV·TSV·TXT 읽기, 전화번호 분리, 정확한 중복 확인, 정렬, 결과 수정, CSV 저장. 한 기기 내 처리. 모임집계의 승인된 단체 편집 화면에서 **명단정리에서 가져오기**로 이동하면, 같은 탭의 sessionStorage를 통해 직접 확인한 명단을 일시 전달하고 모임집계 화면에서 저장 전 검토할 수 있음.
- **주문모아** (`/orders.html`): 상품별 단가와 주문자별 수량을 직접 입력하여 수량·금액을 계산하고 CSV로 다운로드. **1차 버전은 한 기기에서 취합**하며 공유 링크 접수·온라인 결제는 제공하지 않음.
- **카톡정리** (`/chat.html`): 카카오톡 주문 문장을 사람이 읽기 쉬운 표로 분리·직접 수정·CSV 저장. 명단정리/주문모아로 사용자가 직접 보낼 수 있음. 규칙 기반이므로 모든 문장 형태를 자동으로 이해하지는 못함.
- 도구 간 임시 전달 데이터는 20분 이내 sessionStorage에 보관되며, 읽을 때 자동 삭제. 서버로 전송하지 않음. 정리된 데이터의 모임집계 저장은 기존 승인/비밀번호 권한 검사에 따름.
- CSV에는 스프레드시트 수식 실행 가능 문자열을 중화하는 처리를 적용.
- 홈페이지는 도구 카드 검색·분야별 필터와 모바일 반응형 도구 작업 화면 제공.

## 프로그램

1. **모임집계** (`/event.html`): 회원가입 없는 행사 생성, 공개 행사 링크, 담당자 승인 후 단체별 명단·인원 제출, 참가비 합계/입금액 확인, CSV 다운로드. 행사 총괄자와 승인받은 담당자만 개별 명단을 열람합니다.
2. **옛 휴대폰 번호 변환** (`/old-phone.html`): 011/016/017/018/019 → 010 당시 공식 전환용 국번 규칙에 따른 예상 번호 표시. 현재 번호/명의자 조회 불가. 브라우저에서 계산하며 입력번호 저장·전송 없음.

## 행사별 상세명단 항목 및 참가비 직접 설정

- 행사 생성 시 인원수만/이름만/상세 명단 중 택1.
- 상세 명단에서는 이름을 기본 필수 항목으로 유지하고 전화번호·직책·성별·세부 소속·식사 여부·차량번호를 체크박스로 선택. 선택한 기본 항목마다 필수 여부도 지정.
- **＋ 항목 추가**: 직접 입력형 또는 옵션 선택형, 옵션값 여러 개, 필수 입력 여부 지정. 사용자 정의 항목은 최대 12개. 행사 생성 시 서버에 항목 정의 저장.
- **＋ 참가비 추가**: 항목명과 금액을 최대 12개까지 설정. 참가비가 없는 행사도 가능.
- 상세 명단은 참가자별로 각 참가비 항목을 체크(복수 선택 가능). 인원수만/이름만인 경우 단체 담당자가 항목별 적용 인원수를 입력하여 계산. 따라서 한 사람이 등록비와 식비를 동시에 낼 수 있음.
- 총괄자 화면에는 단체별 예상액·입금액 및 전체 예정액·입금액 표시. CSV 파일에 개별 금액 항목과 예상액을 포함.
- 기존 단일 참가비 행사(2026-11-18 이전 생성)는 기존 데이터를 유지하며 자동 합산 규칙도 호환.
- 행사 생성 이후 진행 중인 행사 설정을 수정하는 UI는 아직 제공하지 않으므로, 첫 행사 생성 시 항목과 비용을 확인해야 합니다.

## 모임집계: 총괄자 / 담당자 사용법 및 선택형 비밀번호 보호

- 총괄자는 모임집계에서 행사명·단체명·참가비·참가자 항목을 설정하고 행사 링크를 카카오톡에 공유합니다.
- 담당자는 링크에서 이름/소속을 입력해 승인 요청합니다. 총괄자는 실제 담당자인지 별도로 확인한 뒤 승인 또는 거절합니다. 이름 입력 자체는 신분확인이 아닙니다.
- **기본 모드:** 승인되면 담당 범위의 단체 명단만 조회·수정합니다.
- **비밀번호 보호 모드:** 승인됐더라도 비밀번호를 통과하기 전에는 서버에서 단체 명단 읽기·수정을 차단합니다. 임의 생성 12자리 영문·숫자 코드(약 60비트)를 총괄자가 개별 전달하고 담당자가 입력합니다.
- **행사 링크 페이지에서는 담당자에게 비밀번호를 보여주지 않습니다.** 승인 없이 비밀번호가 노출되면 보호 효과가 사라지기 때문입니다.
- 비밀번호의 해시만 행사별 소유자 전용 Firestore 문서에 보관하고, 담당자는 해시를 제출하여 서버 보안 규칙이 검증한 경우에만 접속 증명 문서를 발급받습니다.
- 총괄자는 기존 행사에서도 비밀번호 보호를 켜거나 끄고 비밀번호를 재발급할 수 있습니다. 비밀번호 변경 시 이전 인증은 무효화됩니다.
- 접속 코드는 총괄자의 현재 브라우저 localStorage에 보관되며, 기기 변경 등으로 분실하면 재발급이 필요합니다. 총괄자 권한 복구 코드는 별도입니다.
- 회원가입 없는 익명 인증 특성상 브라우저 데이터가 삭제되거나 기기가 바뀌면 담당자 승인도 새로 요청해야 할 수 있습니다.
- 이 옵션은 공유 비밀번호에 기반한 **추가 보호 장치**이며 완전한 본인확인·2단계 인증(MFA)은 아닙니다. 코드를 알고 있는 승인자가 타인에게 공유할 수 있으며 요청 수에 대한 서버 측 레이트 리밋은 별도 구축이 필요합니다.

## 행사 서비스 보안 설계

- 행사 메타데이터만 초대 링크를 가진 익명 로그인 사용자에게 공개. **참석자 명단은 Firebase Firestore에서 서버 보안 규칙으로 강제 제한**.
- Firebase Anonymous Auth로 별도 회원가입 없이 임시 사용자 식별. 관리자가 본인이 아는 사람인지 확인한 뒤 승인합니다. **신원 인증과 관리자의 수동 승인은 다릅니다.**
- 담당자는 승인된 자신의 그룹만 조회·수정 가능. 총괄자만 전체 명단, 회비, 담당자 승인, CSV 저장 가능.
- 신규 행사 생성 시 무작위 192비트 복구 코드를 만들고, 해시만 서버에 저장합니다. 이 코드를 잃고 기존 브라우저 인증도 유실되면 행사 관리자 권한을 복구할 수 없습니다.
- 행사당 단체 최대 80개, 단체별 상세 명단 최대 300명. 대형 행사 운영에서는 더 큰 단위의 데이터 모델이 필요할 수 있습니다.
- 개인정보 처리 책임자는 행사 개설자이며, 법률상 필요한 개인정보 안내·동의·보관기간 정책을 마련해야 합니다.

## 운영 선행 조건

1. `sosoking-481e6` Firebase 프로젝트에서 **Firestore 데이터베이스 생성** (Native mode).
2. Firebase Authentication → 로그인 방식 → **익명 로그인 활성화**.
3. Firebase Hosting 웹앱 설정(`__/firebase/init.json`)에 유효한 `apiKey`, `projectId`가 제공되도록 웹앱 등록.
4. GitHub Secrets `FIREBASE_SERVICE_ACCOUNT_SOSOKING_481E6`에 Firestore rules 및 Hosting 배포 권한 보유 서비스 계정이 설정되어 있어야 합니다.

이 선행 조건이 미충족되면 행사 도구는 **데이터를 수집하지 않고 연결 오류를 표시**합니다. 특히 개인정보를 로컬 저장소나 외부 공개 저장소에 임시로 기록하지 않습니다.

```bash
npm install

```
