# SOSOKING — 소소하지만 쓸모 있는 세상

https://sosoking-481e6.web.app/

생활 도구·생활정보 커뮤니티 초기 버전. 기존 하루체크는 /daily.html로 이동하며 기존 localStorage 키와 Firestore 규칙 유지. 기존 행사 데이터는 접근 차단 상태 유지, 삭제하지 않음. 기존 프로그램 백업 archive/pre-daily-check-2026-11-19, 하루체크 기준 커밋 48992d4a11a9daed94f5f71223cb9e55403c69d4.

## 초기 기능
- 프로그램 검색/분류, 기기별 즐겨찾기, PWA.
- 옛 번호 변환: 기존 규칙 재사용, 현재 연락처 조회 불가, 저장 없음.
- 참석 여부 및 단일 날짜 선택 조사: 랜덤 공유 링크, 익명 UID당 응답 1개, 작성자만 집계, 마감/재개. 익명 계정 재생성에 의한 중복 투표는 완전히 막지 못함. 브라우저 데이터 삭제 시 작성 권한 복구 불가. 이전 행사와 별개 컬렉션.
- 커뮤니티·선박 정보: 운영자 승인 전 비공개, 10분에 1건/UID, 출처 URL 입력(선박 필수). 운영자 검토로 공개/반려. 공식 시간표 자동 수집이나 실시간 운항 확인은 제공하지 않음. 오일장 등은 생활정보 제보로 시작.
- 단체 주문 취합, 교대 근무표, 물건 대여 기록: 브라우저에서 처리. 공동 주문/서버 동기화 없음.

## 운영
- Firebase Hosting /__/firebase/init.json 사용. 기존 익명 인증 사용. 운영자는 신뢰할 수 있는 Admin SDK/콘솔에서 moderators/{uid} 등록 후 같은 UID로 /my.html 접속. 일반 사용자에게 권한 부여 금지. 검토할 게시글은 운영자에게만 보임.
- 공유 데이터는 lifePosts, lifePostLimits, lifePolls/{id}/votes. 기존 events 등 데이터 접근 차단 유지. 게시글은 작성자/운영자 삭제 가능. 모임 데이터 삭제/보존 정책 및 계정 복구, 신고·댓글·일반 회원 기능은 추후 개선.
- 개인정보 게시 금지. 모임 링크 공유 범위에 유의. 소규모 서비스로 시작하고 익명 인증 악용, Firestore 사용량 모니터링 필요. 유료 AI API 사용 없음.
- npm install; npm run check; npm run build; node scripts/verify-pwa.mjs; node scripts/verify-seo.mjs --built. GitHub Actions에서 테스트 및 main 배포.

## 후속 작업
- 댓글/신고, 운영자 로그인 및 검토 UI 강화, 선박·오일장 구조화/검증, 다중 날짜 응답, 참가자 관리, 공동 주문, 회비, 회원 동기화 및 삭제 정책.

## 2.0 — 핵심 서비스 중심 개편
- 공개 도구: 모임·참석 조사(복수 날짜, 선택 투표, 동반 인원, 마감, 실시간 집계, CSV), 선박 시간표(지역·항로·선사·운항 시간·확인일·유효기간·출처 및 공식 사이트), 공동 주문(공유 메뉴와 수량, 금액, 응답 수정/철회, CSV), 옛 번호 변환, 교대근무(프리셋, 월 이동, 인쇄, ICS), 지역 생활정보 커뮤니티.
- 커뮤니티: 카테고리와 검색, 글 상세, 로컬 저장/공유, 검토 기반 댓글, 오류/신고, 내 글/댓글 삭제, 운영자 승인/반려/신고 처리. 공개 글 조회 최대 200건. 인덱스가 없으면 제한된 목록을 클라이언트에서 정렬.
- Firebase 익명 인증 유지. Google 계정 연결/로그인은 Firebase Console에서 Google 제공자를 활성화해야 이용할 수 있다. 운영자 UID는 기존 moderators/{uid} 문서로 관리자만 설정한다. 운영자 등록 없이 승인/게시를 우회하지 않는다. 익명 계정 중복 이용 방지는 제한적이다.
- 기존 lifePolls와 votes는 유지하며 v2 스키마 추가. 기존 개인 주문·하루체크·대여 기록 보존. 하루체크/대여는 메인·사이트맵에서 제거하고 기록 회수용 페이지/백업을 제공. 이전 버전 백업 브랜치 archive/pre-premium-2026-11-24. 실제 선박 시간은 임의 등록하지 않으며 공식 출처 링크를 제공한다.
- 검증: Node 단위 테스트, PWA/SEO 및 배포 파일 검사, Firebase 실제 보안 규칙과 합성 데이터 smoke 테스트. 배포 및 검사 실패를 숨기지 않는다.

## 2.1 도구 · 생활정보 · 커뮤니티
- 상하단 메뉴 홈/생활 도구/생활정보/커뮤니티/마이페이지. 선박은 생활정보에 포함. 메인에서 프로그램과 생활정보 영역 분리.
- 소규모 포구 도선 15개 항로(22개 조건별 시간표)를 2026-11-24에 공개 자료에서 확인. 남당항–죽도, 당진·화성, 강화, 고흥, 진도, 신안, 거제. public/data/local-ferry.json에 출처 URL·종류·게시일(있는 경우)·확인일·왕복 시각·계절별 운항 조건과 주의사항 보관. 실시간 운항이나 전국 전체를 보장하지 않음. 개인 블로그 자료는 별도 표시하며 원문 확인과 운항 문의 안내. 미확인 귀항편을 추정하지 않음. 지역·항구·섬·출처 검색, CSV 및 제보 제공.
- 신규 모임비용 정산: 원 단위 균등 분배와 송금액 계산, CSV/복사, 서버 전송 없음.
- 생활정보: 폐가전 수거, 공공시설 예약 등 공식 안내 및 동네 정보 제보 연결.

## 3.0 현장 정보 사전
- 소형 도선 24개 항로(기존 15+신규 9), 현장 정보 12건. 자료 원문 URL, 확인일, 출처 종류 포함. 출항 시간 없이 호출하는 도선도 수록. 전국 전체나 당일 운항을 보장하지 않음.
- 사용자 시간표 등록: 왕복, 호출 방식, 운항 조건, 요금, 승선 위치, 현장/전화 확인 근거. 온라인 출처는 URL 필수, 현장/전화는 근거 필수. 검토 승인 후 기존 정적 항로 검색에 통합. 변경은 수정 제보로 재검토.
- 생활정보 사전: 분류 검색과 사용자 생활정보 등록, 정보 요청 게시판. 확인 자료 없는 항목은 빈 상태로 표시. 별도 사진 저장, 알림, 자동 수집은 미구현.

- 단체 행사 준비: 차량·조 정원에 맞춘 자동 배정(초과 인원 별도 표시), 준비물·담당자·완료 체크리스트, 기기 저장, CSV/복사. 실시간 공동 편집은 제공하지 않음.

## 자동 병합 및 배포
- 저장소 소유자가 이 저장소 내 feature/ 브랜치에서 만든 일반 PR에 한해 check 및 integration 성공 후 자동 병합. 초안, 외부 저장소 PR, 타 계정 실행, 검사 실패, 변경된 head 또는 main은 자동 병합하지 않음.
- 자동 병합에는 해당 job에만 GitHub Actions write 권한을 부여하며, PR 코드를 checkout하거나 실행하지 않음. 병합 후 main의 deploy.yml을 workflow_dispatch로 실행하여 재검사 및 Firebase 배포. Actions 권한 제한으로 병합/dispatch가 거절되는 경우 실행 로그에 실패로 남김. 외부 기여 PR은 수동 검토.
- GitHub 기본 auto-merge는 branch protection 필수. 현재 접근 권한으로 설정을 변경할 수 없어 저장소 워크플로 방식으로 구성.

## 사소한 기억
- 일회성 구매·가입일 및 반복 생활 기록, 날짜/금액/메모 이력, 경과일과 다음 예정일(일/개월/년 주기 또는 직접 지정), 검색·분류, 오늘 기록, 수정·삭제, JSON 백업/복원·CSV 내보내기. 예시 항목은 선택 시 양식에만 입력됨.
- 개인 기록은 브라우저 localStorage 전용이며 서버·계정 동기화 및 푸시 알림 없음. 삭제 전 백업 권장. 반복 일정은 마지막 실제 기록 기준이며 월말·윤년을 보정함.

## 4.0 간결한 홈 / 임원선출
- 홈 삼행시 및 3대 메뉴, 별도 도구 카탈로그(개인 3개, 단체 5개), 생활정보 등록 진입점, 게시판 4개 그룹(기존 분류와 데이터 보존).
- 기존 도구: 사소한 기억 상세옵션 접기, 번호 일괄변환(전환 규칙만), 근무표 CSV 및 이번 달, 개별 부담 정산, 설문/공동주문 집계 인쇄, 행사 준비 수정 및 인쇄.
- 임원선출: 직책별 개설, 2~100명의 무작위 코드 발급, 추천과 투표 각각 1회, 후보 1~5명, 단독 후보 찬반/복수 후보 단일 선택, 기권, 단계별 마감, 운영자 마감 후 집계·CSV. 코드는 해시로 저장하지만 관리자와 운영 인프라가 기록을 연결할 수 있으므로 완전한 비밀투표가 아님. 소규모 내부 선거 보조용이며 선거권자 1인당 1코드 배부는 주최자가 책임짐. 사진 업로드·기록 클라우드 동기화·결선 자동화·공동편집·알림은 미구현.

- 교대근무표는 신규 도구에서 제외하고 마이페이지 이전 프로그램 보관 영역에 유지(검색 노출 제외). 개인 기록 도구명은 '언제 했더라?'로 변경. 저장 키와 주소는 그대로 유지하여 기존 데이터와 즐겨찾기를 보존.
