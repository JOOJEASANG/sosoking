# 그때 그 번호

소소킹의 차기 웹앱입니다. 01X 번호 변환, 옛 주소록 정리, 추억방을 한곳에서 제공합니다.

## 기능
- 011·016·017·018·019 → 010 전환 규칙 계산
- 여러 번호 일괄 변환과 CSV 다운로드
- 기기 내 추억 주소록과 CSV 백업
- 오랜만에 보내는 안부 문자
- PC통신 스타일 로컬 채팅 체험
- Firebase 인증 및 초대 링크를 이용한 비공개 실시간 추억방 (설정 완료 후 활성화)
- 7일 유효 초대 링크 및 마지막 발급 링크 취소
- 추억방 운영 종료 (새 대화 차단, 기존 데이터 보존)
- 방 멤버 전용 '우리들의 추억 게시판', 작성자/방장 글 삭제
- 작성자/방장 채팅 메시지 삭제

## 로컬 실행

```bash
npm install
npm run check
npm run dev
npm run build
```

## 실제 채팅을 활성화하려면

1. Firebase 프로젝트의 웹 앱 설정을 `reconnect-preview/firebase-config.js`에 입력합니다.
2. Firebase Authentication에서 이메일/비밀번호 로그인 방식을 켭니다.
3. Cloud Firestore 데이터베이스를 만들고 `firestore.rules`를 검토한 뒤 배포합니다.
4. 서로 다른 계정으로 방 만들기, 링크 초대, 참가, 메시지 전송을 테스트합니다.

현재 자동 배포 워크플로는 Hosting만 배포합니다. Firestore 규칙 배포는 별도로 검토해야 합니다.

## 개인정보 및 운영 유의사항

변환 결과는 과거 규칙에 따른 **추정 번호**입니다. 현재 사용 번호·가입자·통화 가능 여부를 조회하지 않습니다.
번호 변환 및 주소록 내용은 서버로 보내지 않습니다. 추억 주소록은 브라우저 저장소에 보관되므로 공용 기기에서 사용 후 지워야 합니다.
회원 계정과 실시간 채팅은 Firebase에 저장됩니다. 초대 코드를 가진 가입자는 방에 들어올 수 있습니다. 현재 취소 버튼은 해당 화면에서 마지막으로 발급한 링크에만 작동합니다. 개별 링크의 전체 관리, 신고·차단, 자료의 실제 삭제 및 개인정보 처리방침은 공개 전에 보완해야 합니다.

## 배포 전 확인

- GitHub Actions 신규 사이트 빌드 확인
- Firebase Auth와 Firestore Security Rules를 실제 프로젝트에 적용
- 서로 다른 테스트 계정 2개로 정상 초대·만료·무효화·종료·권한 거부 확인
- 추억방 종료는 데이터를 영구 삭제하지 않습니다. 삭제 요청 처리 절차 별도 필요
- 사진 앨범/사진 업로드 기능은 아직 구현하지 않았습니다.
